# 2026 Ai-EYES DA 파트 연말 프로젝트

## 청년 실업률과 고용보조지표의 차이, 그리고 청년 고용 변화

공식 실업률만으로 청년의 고용 상황을 얼마나 설명할 수 있을까? 이 프로젝트에서는 경제활동인구조사 자료로 공식 실업률과 고용보조지표를 다시 계산하고, 두 지표가 서로 다른 사람들을 집계하면서 생기는 차이를 살펴본다. 청년 취업자 수의 변화는 인구 변화와 고용률 변화로 나눠 본다. 직업별 자료를 확보하면 생성형 AI 노출도와 청년 고용 변화의 관계도 분석한다.

팀원은 윤성제·이유현·손은서다. 이 문서는 2026년 11월 4일 확인한 [Notion 계획서와 코멘트](https://app.notion.com/p/DA-40aa9c5fcb63809d9f3eeae7a679e915)를 반영했다. 개인별 담당은 아직 정하지 않았다.

현재 저장소에는 수집 함수, 지표 계산식, 인구구성 분해 함수와 노트북 초안이 있다. 실제 데이터와 분석 결과는 포함되어 있지 않다. 아래 내용은 앞으로 수행할 분석 계획이며, 최신 실업률 수치나 AI의 고용 효과를 확인한 결과가 아니다.

청년은 15~29세로 정한다. 잠정 분석 기간은 `2015-01~2026-08`이며 [`src/config.py`](src/config.py)에 설정되어 있다. 공통으로 확보되는 기간과 직업·산업분류 개정 여부를 확인한 뒤 최종 기간을 정한다. 분류가 달라지는 구간을 확인 없이 이어 붙이지 않는다.

'쉬었음'과 취업준비 인구를 추가하는 자체 지표는 선택 과제로 남긴다. 필요한 MDIS 변수가 제공되고 중복을 제거할 수 있을 때만 계산한다. 이 지표를 공식 통계나 실제 실업률이라고 부르지 않는다.

## 2. 지표와 검증 기준

기호는 실업자 `U`, 경제활동인구 `L`, 시간관련추가취업가능자 `T`, 잠재경제활동인구 `P`로 둔다. `P`는 잠재취업가능자와 잠재구직자의 합이다.

| 지표 | 계산식 |
|---|---|
| 공식 실업률 | `U / L × 100` |
| 고용보조지표1 | `(U + T) / L × 100` |
| 고용보조지표2 | `(U + P) / (L + P) × 100` |
| 고용보조지표3 | `(U + T + P) / (L + P) × 100` |

[공식 실업률 설명](https://www.index.go.kr/unity/potal/main/EachDtlPageDetail.do?idx_cd=1063)과 실제 사용할 통계표의 설명자료를 함께 확인한다. 지표의 집계 범위 차이와 표본오차를 구분한다. 두 지표의 격차만으로 공식 통계가 잘못됐다고 판단하지 않는다.

재계산할 때는 같은 월·연령·성별·단위·계절조정 여부의 공표값과 비교한다. 가중치의 단위와 배율은 해당 연도 MDIS 이용지침에서 확인한다. 가중치가 명 단위라면 천 명 환산에 `/1000`을 사용한다. 12개월을 합친 뒤 `/12000`으로 나누는 방식은 월 가중치가 같은 정의이고 12개월이 모두 있는 연평균 인원 계산에만 해당한다.

공표값과의 차이 `0.1%p`를 초기 점검 기준으로 둔다. 초과하면 연령 필터, 변수 분류, 가중치, 공표값 반올림부터 확인한다. 기준 이내라는 이유만으로 계산이 정확하다고 확정하지 않는다. [`validate_against_published`](src/indicators.py)는 결측·무한대도 실패로 표시하며, 판정에는 반올림 전 차이를 사용한다.

표본설계와 필요한 변수를 확보하면 조사설계를 반영한 불확실성 추정을 검토한다. 현재 `rse_confidence_interval`은 실업자 수의 RSE만 반영하고 분모의 오차는 무시하는 근사 함수다. 가정한 RSE를 넣은 결과는 민감도 분석으로만 제시하며 공식 신뢰구간이나 두 지표 차이의 유의성 검정으로 해석하지 않는다.

KOSIS 표 ID와 MDIS 변수명은 [`docs/data_dictionary.md`](docs/data_dictionary.md)에 기록한다. `config.TABLES`에는 확인이 필요한 후보 ID도 있으므로, 코드에 값이 있다는 이유만으로 사용을 확정하지 않는다. 아직 `None`인 표는 ID를 확인한 뒤 수집한다. API의 항목·분류 파라미터도 표마다 확인해야 한다.

MDIS에서 필요한 변수를 구하지 못하면 해당 지표의 재계산은 보류하고 KOSIS 공표값 비교까지 수행한다. 세부 직업코드나 연결 가중치가 없으면 AI 분석의 범위를 줄인다. 원자료와 API 키는 커밋하지 않는다. `data/raw`, `data/processed`, `data/external`의 자료 파일은 Git에서 제외된다.

## 4. 그래프와 통계분석 계획

| 그래프 | 그리는 이유 | 함께 표시할 내용 |
|---|---|---|
| 공식 실업률·고용보조지표1·2·3 선그래프 | 각 지표의 수준과 변화 시점을 비교 | 연령, 기간, 계절조정 여부, 출처 |
| 보조3−공식 실업률 격차와 구성인원 추이 | 격차 변화와 관련된 인구집단을 확인 | 인원과 비율의 단위, 분모 차이 |
| 공표값 대비 재계산값 차이 그래프 | 어떤 시점·집단에서 재현이 어긋나는지 점검 | 초기 점검 기준 ±0.1%p, 결측 기간 |
| 인구효과·고용률효과·교차항 막대그래프 | 취업자 수 변화를 세 항으로 나눠 비교 | 기준·비교 시점, 합계와 실제 증감의 일치 여부 |
| 직업별 AI 노출도와 청년 취업자 수 변화율 산점도 | 직업별 관계와 이상치를 탐색 | 비교 기간, 표본 규모, 연결되지 않은 직업 비중 |

계절성은 같은 정의의 공식 계절조정 공표치가 있는지 먼저 확인한다. 없으면 전년 동월 비교를 우선하고, 별도 계절조정이 필요한지 검토한다. X-13이나 STL을 적용하면 설정과 원계열 비교를 남긴다. 두 방법의 결과를 같은 것으로 취급하지 않는다. 인구구성 조정도 공식 공표자료와 대조하고 기준인구를 명시한다.

AI 노출도는 직업의 업무가 생성형 AI의 영향을 받을 가능성을 평가한 지수다. 실제 현장의 AI 사용 비중이나 일자리 감소율이 아니다. ILO 지수는 업무별 자료, 전문가 평가와 AI 예측을 결합한다. 이 프로젝트에서는 직업 단위로 사용하며 산업 전체의 노출도로 바로 해석하지 않는다.

회귀분석은 직업별 청년 취업자 수 변화율을 종속변수, AI 노출도를 설명변수로 두는 단순 모형부터 검토한다. 변화율의 기준·비교 기간은 공통 자료 범위를 확인한 뒤 정한다. 기준시점 취업자 수가 0인 직업은 변화율을 계산하지 않고 별도 기록한다. 직업 연결이 일대다일 때는 근거 없는 단순 평균 대신 연결 규칙과 가중치의 확보 가능성을 먼저 확인한다.

노출도 계수의 95% 신뢰구간과 `계수=0` 검정 결과를 제시하고, 관측 수·이상치·이분산을 점검한다. 추론에는 `statsmodels`를 사용하고 `scikit-learn`은 비교 모형과 예측 오차 점검에 활용할 계획이다. 직업·기간별 자료가 충분하고 사전 추세와 비교집단을 점검할 수 있을 때만 DID를 추가 검토한다. 기존 `06_ai_exposure_did.ipynb` 파일명은 유지하되, DID 수행이 확정된 것은 아니다. 경기·인구·직업구성 등 다른 요인이 섞이므로 AI가 고용 변화를 일으켰다고 결론 내리지 않는다.

## 6. 저장소와 실행 방법

- `src/kosis.py`: KOSIS API 호출과 CSV 저장
- `src/indicators.py`: 공식·보조·자체 확장지표, 공표값 비교, RSE 근사
- `src/decompose.py`: 인구·고용률 분해와 연령 표준화
- `notebooks/01~06`: 수집, 탐색, 재계산, 인구구성 분해, 선택 확장지표, AI 관계 분석의 초안
- `docs/`: 데이터 사전과 참고자료
- `reports/figures/`: 그래프 저장 위치
- `tests/`: 계산식과 결측·검증 오류를 확인하는 테스트

Python 3.10 이상을 권장한다. macOS/Linux에서는 다음 순서로 준비한다.

```bash
git clone https://github.com/muju0629/DA_Final_Project.git
cd DA_Final_Project
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
# .env의 KOSIS_API_KEY에 본인 키 입력
jupyter lab
```

Windows에서는 가상환경을 만든 뒤 `.venv\Scripts\activate`로 활성화하고 `copy .env.example .env`를 사용한다. API 키는 [KOSIS 공유서비스](https://kosis.kr/openapi/index/index.jsp)에서 발급받는다. 저장소 루트에서 Jupyter를 실행하고 `notebooks/`의 파일을 연다. 공통 모듈을 찾는 노트북의 상대경로는 노트북 폴더를 기준으로 한다.

`01_collect.ipynb`는 API 키와 표별 파라미터 확인이 필요하다. 나머지 노트북은 현재 제목·작업 순서·라이브러리 불러오기 중심이며, 데이터 처리와 분석 셀은 앞으로 작성한다. 전체 노트북을 실행해도 분석 결과가 완성되는 상태는 아니다.

X-13 실행파일은 기본 설치에 포함하지 않는다. 필요할 때 운영체제에 맞는 실행파일을 별도로 설치하고 `X13PATH`를 설정한다. `x13binary`는 현재 Mac 환경에서 설치 후보를 찾지 못해 필수 의존성에서 제외했다.

테스트는 실제 데이터나 API 키 없이 실행한다.

```bash
python -m unittest discover -s tests -v
```

## 7. 협업과 남은 확인 사항

작업은 별도 브랜치에서 진행하고 PR로 검토한다. 노트북 출력은 지운 뒤 커밋하며, 공통 계산식은 `src/`에서 관리한다. 그래프 파일에는 질문과 내용을 알 수 있는 이름을 붙인다.

우선 확인할 것은 KOSIS 표·분류코드, MDIS 변수·가중치와 직업코드 제공 수준, 공식 계절조정 자료, ILO–KSCO 연결 가능 여부다. 데이터가 확보되면 단위·누락 월·중복 행·분류 개정을 점검하고 데이터 사전을 채운다. 참고문헌은 [`docs/references.md`](docs/references.md)에 모았으며, 검토 후보의 수치나 결론은 원문 확인 전 인용하지 않는다.
